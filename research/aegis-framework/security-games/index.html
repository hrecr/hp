CORE GAMES

Eight independent AKE experiments.

Correctness

Purpose: Agreement of honest partnered sessions. Central event: Accepted partners disagree.

Needs: Acceptance, partnering, context, session key

AKE session-key secrecy

Purpose: Protect a fresh accepted session key. Central event: Adversary distinguishes real from random.

Needs: Session key, exposure, freshness, Test

Mutual authentication

Purpose: Bind acceptance to a unique matching peer. Central event: Accepted session lacks a valid partner.

Needs: Acceptance, peer identity, partnering

Forward secrecy

Purpose: Protect past keys after later compromise. Central event: Past Test key is distinguished after corruption.

Needs: Acceptance time, corruption time, freshness

KCI resistance

Purpose: Resist impersonation after victim compromise. Central event: Adversary impersonates a different peer.

Needs: Credentials, corruption, peer binding

UKS resistance

Purpose: Prevent identity disagreement for a shared key. Central event: Partners agree on key but not peer identity.

Needs: Keys, identities, credentials, partnering

Replay resistance

Purpose: Prevent stale messages creating fresh acceptance. Central event: New acceptance has only an old matching trace.

Needs: Transcript, state, freshness, matching

Downgrade resistance

Purpose: Protect authorized algorithm negotiation. Central event: Session accepts an unauthorized weaker suite.

Needs: Suite negotiation and authenticated context

IOT ROBUSTNESS GAMES

Parameterized claims need explicit profiles.

State reveal

Requires leakage profile Λ; never report this property without the profile.

Desynchronization

Requires Sync, disturbance bound q, and recovery bound ρ.

Energy exhaustion

Requires a concrete cost metric, pre-authentication boundary, and bound Γ.
