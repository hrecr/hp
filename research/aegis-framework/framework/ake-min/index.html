FRAMEWORK MODULE · WORKFLOW STEP 03

IoT-PQ-AKEmin

A minimal common model for inspecting post-quantum IoT AKE protocols. It provides a shared inspection language for parties, sessions, messages, credentials, fresh contributions, state, adversary queries, and security goals.

SECURITY GOALS

Eleven independent targets.

Correctness

Honest partnered sessions accept and agree on context and key.

AKE session-key secrecy

A fresh session key is indistinguishable from a random key.

Mutual authentication

An authentication-fresh accepted session has a unique matching peer session.

Forward secrecy

Post-acceptance long-term compromise does not reveal past session keys.

KCI resistance

Compromising one party does not enable impersonation of another party to the victim.

UKS resistance

Parties do not share a key while disagreeing about peer identity or credential.

Replay resistance

Old messages do not cause a new session to accept without a live matching execution.

Downgrade resistance

Negotiation interference does not force an unauthorized weaker suite.

State-reveal resilience

Parameterized by an explicit leakage profile Λ.

Desynchronization resilience

Parameterized by disturbed-session bound q and recovery bound ρ.

Energy-exhaustion resistance

Parameterized by a cost model and bound Γ.

HANDOFF TO AKEGEN

Missing values stay visible.

AKEmin records what the protocol actually exposes. AKEgen then constructs canonical transcripts, binding contexts, session identifiers, authentication contexts, KDF contexts, freshness maps, and partnering relations. Missing values are not silently inserted into the protocol.
